# 涟漪 Ripple

涟漪是一个由事件变化驱动的日程助手。Android 版读到迟到、改期或取消通知后，会找出相关日程，沿前置关系计算后续影响，并为符合条件的时间变动提供可选的调整方案。用户确认后，涟漪才将所选方案写入日程。

## 看展演示

在空白日期点「创建看展示例」。初始安排是 14:00 与小明集合、14:30 入场参观、17:00 乘车返程。

1. 点「模拟朋友晚到 40 分钟」，把示例集合时间推迟到 14:40。加上两段转场，预计最早 14:50 到展馆、17:10 到返程站。
2. 点「查看冲突」，对比两套方案的时间、时长、地点和前置关系。

   | 方案 | 入场与会合 | 返程 |
   | --- | --- | --- |
   | 一起看展 | 使用 15:00 的演示场次，参观 90 分钟 | 17:00 |
   | 保留原预约 | 14:30 入场，16:30 在展馆出口与小明会合 | 17:00 |

3. 选中方案后点「确认并更新行程」。返回时间轴可核对结果，重启后仍可查看已保存的安排。

看展场次来自示例数据。日程和方案计算都在本机完成。

## 日程如何处理变化

| 功能 | 入口与行为 |
| --- | --- |
| 日程管理 | 用右下角加号添加行程，可设置时间、时长、地点、参与人、时间约束和高、普通、低三级优先级。在顶部切换日期，在「关系」页查看前置行程和转场时间。 |
| 智能关联 | 在「设置 → 查看最近通知」打开详情。明确匹配时显示关联行程和依据，候选接近时请用户选择。点「查看关联行程」跳转到对应日期。 |
| 影响传播 | 「事件影响预览」对照原定时间和预计最早时间，说明延误会在哪里继续传递、在哪里被缓冲吸收。取消通知会列出需要核对的后续安排。 |
| 智能重规划 | 当天可调整行程发生可确定的时间变化时，从通知详情点「对比重规划方案」。也可从时间轴的「查看冲突」进入。涟漪保留固定时间，优先减少对高优先级行程的改动。 |

行程按日期保存在本机。旧版未分日期的行程在首次升级时归入当天，旧行程优先级默认为普通。

## 接入 Android 通知

1. 在「设置 → 允许读取通知的应用」开启系统通知读取权限，再打开总开关并勾选需要读取的应用。
2. 在「设置 → AI 模型设置」填写 API 密钥。默认使用 DeepSeek 的`deepseek-flash`，也可以配置支持 Chat Completions JSON 输出的 HTTPS 服务。
3. 在「查看最近通知」打开一条变动通知，核对关联依据和影响预览。体验看展场景时，可让小明发来「我今天下午可能要晚到 40 分钟」。

系统通知来自勾选的应用，最近 7 天内最多保留 50 条。所选模型服务会收到通知来源、标题、正文和接收时间。含常见验证码提示的通知只在本机保存。API 密钥使用 Android Keystore 加密后存于本机。

有明确时间的新增安排会加入对应日期。再次打开涟漪时，可以逐项选择是否保留。时间待补全的新增安排可从通知详情手动加入。重复通知与已编辑的日程时间冲突时，涟漪会提供保持现状、改为通知时间或另加一项的选择。通知里的「今天」和「明天」按接收时的本地日期解析。

通过 APK 安装后，如果系统提示「受限制的设置」，可在「涟漪」应用信息页的右上角菜单选择「允许受限制的设置」，再返回通知读取设置。[Android 帮助](https://support.google.com/android/answer/12623953?hl=zh-Han)

## 本地开发

使用 Flutter 3.50.1 和 Dart 3.14。构建 Android 版还需要 JDK 17 和 Android SDK 36。Windows 上请使用纯英文的工程与 SDK 路径，可以用临时盘符映射工作区。

```bash
flutter pub get
flutter analyze
flutter test
flutter build apk --release
```

APK 生成于 `build/app/outputs/flutter-apk/app-release.apk`。

Web 版可体验日程编辑、看展示例和方案确认。Android 版提供系统通知读取。

```bash
flutter build web --no-web-resources-cdn
python -m http.server 8781 --bind 127.0.0.1 --directory build/web
```

启动后打开 [本机预览](http://127.0.0.1:8781/)。
